# Architecture

`apps/web` is a React/TypeScript client. `services/api` owns REST, SQLite persistence, controlled upload/artifact storage, background preprocessing, and the OCR subprocess supervisor. `engine/sldgraph` owns canonical models, graph reasoning, inspection, text intelligence, validation, and exporters. `sldforge` creates graph-first controlled synthetic drawings and ground truth.

The stable core Python environment communicates by JSON-lines stdin/stdout with `scripts/ocr_worker.py` in `.venv-sldgraphx-ocr-clean`. The worker uses explicit model paths under `models/ocr/paddle`, returns normalized page geometry, and cannot expose worker paths through the API. Worker unavailability, timeout, crash, or malformed output fails only the `ocr` analysis stage; `/api/health` still reports the core as healthy.

OCR regions become immutable `TextEvidence` records with separate OCR, normalization, and semantic confidence plus `TextReviewAction` audit records. Raster uploads remain unassigned until a future detector exists. The association engine is exercised only against controlled SLDForge ground-truth geometry in this milestone. Later perception branches converge on the canonical `ElectricalGraph`.

Milestone 3 adds a second JSON-lines worker boundary: `scripts/symbol_worker.py` executes in `.venv-sldgraphx-detector` with an explicit `models/detector/symbol-svm-v1.joblib` path. The core imports only typed `SymbolRequest`/`SymbolResponse` models, supervises worker health and failure mapping, and never imports OpenCV or scikit-learn. The worker proposes local contour regions, classifies them with HOG + calibrated linear SVM, detects busbars with a separate deterministic geometry rule, maps tile coordinates back to the page, and applies class-aware NMS.

`SymbolEvidence`, `TextSymbolAssociation`, and `SymbolReviewAction` are durable SQLite evidence/audit records. Association is a transparent spatial-semantic ranking over persisted text and symbol candidates; it is not topology inference.

Milestone 4 adds an in-core OpenCV topology module after persisted OCR/symbol evidence. It masks symbol and text regions before directional morphology, selected angled-line tracing, and Zhang-Suen skeletonization. Busbars are first-class detector/geometry evidence. Skeleton branch points only become connected junctions when compact dark-dot evidence exists; otherwise line crossings remain explicitly ambiguous. Symbol templates generate named terminals with a resolution-scaled snap radius. Conductor endpoints produce scored candidate edges; simple masked gaps are retained only as pending bridge proposals. Deterministic repair deduplicates competing terminal pairs and validation records orphan/degree issues without inventing connectivity.

`ConductorEvidence`, `BusbarEvidence`, `JunctionEvidence`, `TerminalEvidence`, `ConnectionCandidate`, `PhysicalConnection`, `TopologyIssue`, and immutable `TopologyReviewAction` records are durable SQLite evidence. M5 derives rather than mutates this layer. `SourceAssignment`, `Feeder`, `FeederPath`, `ValidationIssue`, `ElectricalReviewIssue`, `SwitchState`, `ScenarioRun`, and export receipts persist per analysis. The source-feeder engine uses NetworkX locally for physical/operational/semantic graph views. Edit recomputation never invokes OCR, detector, or topology extraction. API endpoints serve source, feeder, trace, validation, review, scenario, reconstructed SVG, and safe export payloads.
