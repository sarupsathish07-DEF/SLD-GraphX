# Data provenance

User uploads remain local in controlled `var/uploads/<project>/<drawing>/` storage. The database stores identifiers, sanitized filename, MIME type, SHA-256, size, inspection evidence, and safe relative artifact references; it never stores image blobs or exposes local paths to the browser.

Milestone 1 render/preprocessing artifacts are stored under controlled `var/renders/<analysis-run>/` storage. Each has an opaque artifact ID, SHA-256, MIME type, relative path, page, dimensions, and generation configuration. The artifact API validates the resolved path remains under `var/` before serving it.

SLDForge samples are project-generated controlled synthetic data marked `synthetic_ground_truth`. Their manifests identify seed, topology, canonical equipment/terminals/connections/switch states, rendered text, and exact source-to-feeder paths. They are not real measurements or a claim about field generalization.

M5 semantic outputs retain physical connection IDs, path confidence/weakest edge, source/feeder resolution, uncertainty flags, validation code, review-risk factors, switch-state provenance, and engineer actions. Export JSON/CSV uses stable IDs and deliberately excludes controlled-storage paths.

Milestone 2 persists raw OCR text permanently alongside its normalized candidate, type, three independent confidence dimensions, normalized box/polygon, page, rotation, engine/model, provenance, review state, and association evidence. Engineer edits are separate `TextReviewAction` records; they never overwrite raw OCR. OCR model payloads are local ignored files in `models/ocr/paddle`; the tracked manifest stores reproducibility checksums, not model binaries.

Milestone 3 SLDForge symbol-v1 is project-generated controlled synthetic data. `scripts/create_symbol_dataset.py` deterministically emits 75 whole drawings (750 annotated objects), canonical JSON, COCO, YOLO, and a tile manifest. Drawing-level splits precede tiling so no parent drawing crosses train, validation, test, or style holdout. Generated images, annotations, and benchmark manifests are ignored because the tracked generator/spec reproduce them. `SymbolEvidence` stores candidate geometry, confidence, original and current class, tile origin, worker engine/model, local provenance, review state/reason, and immutable engineer action history. Its linked `TextSymbolAssociation` stores rule provenance and score factors. This is evidence provenance, not electrical connectivity provenance.

Milestone 4 topology-v1 is project-generated controlled synthetic data. `scripts/create_topology_benchmark.py` deterministically produces 24 drawings: six topology families across styles A/B/C test and style D holdout. Each hidden manifest entry preserves equipment classes/boxes, terminals, physical equipment endpoint pairs, critical-edge flags, rendered text, and controlled topology metadata. Generated images, manifest, degradations, and benchmark results are ignored; the tracked generator/spec reproduce the corpus. Runtime records raw traces, buses, junction/crossover evidence, terminals, candidate score components, selected physical edges, validation issues, and immutable review actions. This is local image-evidence provenance, not source/feeder, operational, or real-world provenance.
